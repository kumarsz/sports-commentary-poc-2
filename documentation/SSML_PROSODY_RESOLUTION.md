# SSML Prosody - Issue & Resolution

**Date:** December 28, 2025  
**Issue:** SSML prosody markers were being spoken as text instead of being processed as speech instructions  
**Status:** ✅ **RESOLVED** - Reverted to simple dramatic text approach

---

## The Problem

The initial approach was to embed SSML prosody markers in the text:

```
"[FAST]Stokes fires in a length ball, Richardson defends it back to mid-on, no run![/FAST]"
```

Then convert them to SSML XML tags:

```xml
<prosody rate="fast">Stokes fires in a length ball, Richardson defends it back to mid-on, no run!</prosody>
```

**But the issue was:** Web Speech API's `SpeechSynthesisUtterance` **does NOT process SSML markup**. The tags were being spoken as literal text by the browser's speech synthesizer.

User heard: "prosody FAST ... Stokes fires ... prosody ... prosody"

Instead of: "Stokes fires..." (spoken fast)

---

## Root Cause

**`SpeechSynthesisUtterance` limitations:**
- Does not support SSML XML markup
- Only supports plain text input
- No native prosody control interface
- Different browsers have different (limited) SSML support

This is a well-known limitation of the Web Speech API.

---

## The Solution

**Revert to the simpler, more effective approach:**

1. **Remove SSML prosody markers** from the conversion flow
2. **Use only the dramatic text** generated by OpenAI
3. **Strip markers** to show clean text to users
4. **The real value** is the dramatic/engaging commentary content itself, not synthetic prosody

### What Changed

#### Backend: `server/openai-commentary.js`
**Removed:** Prosody marker instructions from OpenAI prompt  
**Before:**
```javascript
"CRITICAL: Include prosody markers to create natural speech rhythm...
- [HIGH] text [/HIGH] - For excitement
- [LOW] text [/LOW] - For tension
- [EMPHASIS] text [/EMPHASIS] - For strong emphasis"
```

**After:**
```javascript
"Tone: Dramatic, enthusiastic, knowledgeable. Not stiff or analytical.

Examples:
"Four! Beautiful shot down the ground!"
"And he's out! Bowled by a fantastic delivery!"
"Quick single taken!"
```

#### Frontend: `client/src/components/LiveMatch.js`
**Removed:** `convertToSSML()` function (was converting markers to SSML tags)  
**Updated:** `getCommentaryForMode()` to strip markers and return clean text

**Before:**
```javascript
return convertToSSML(ball.aiCommentary); // Returns SSML markup
```

**After:**
```javascript
return stripSSMLTags(ball.aiCommentary); // Returns clean dramatic text
```

**Kept:** `stripSSMLTags()` function (handles any markers in stored data)

### 2. **The Drama is in the Content** ✅
OpenAI generates genuinely dramatic commentary:

This is engaging and natural-sounding without needing synthetic prosody.

Works on all browsers without SSML support worries (Chrome, Firefox, Safari all handle plain text).

### 5. **Simple & Maintainable** ✅
No complex regex conversions, no prosody configuration—just speak the text.

## Data Flow (Simplified)

```
1. User selects OpenAI mode
2. Backend: OpenAI generates dramatic text
   "And he's out! Bowled by a spectacular delivery!"
3. Frontend: Stores in ball.aiCommentary
4. When user plays audio:
   getCommentaryForMode() → stripSSMLTags() → clean text
   "And he's out! Bowled by a spectacular delivery!"
5. Web Speech API speaks the text
6. User hears: Exciting, dramatic commentary
```

## Future Enhancement (Post-MVP)

For better prosody control later:

### Option 1: Professional TTS Service
- Use Google Cloud Text-to-Speech or Azure Speech Services
- These properly support SSML markup
- Trade-off: Adds backend API calls and costs

### Option 2: Multiple Segments
- Split commentary into smaller segments
- Speak each segment with different `rate` and `pitch` properties
- More complex but works with Web Speech API
- Example: Speak "Four!" with `rate=1.5`, then "Beautiful shot" with `rate=1.0`

### Option 3: Popular Voice Personas (V2)
- Sample professional cricket commentators (Harsha Bhogle, Aakash Chopra)
- Use voice cloning or HQ voice packs
- Better quality than browser TTS anyway
