# Pitch Audio Feature - Investigation & Solution

**Date:** December 28, 2025  
**Issue:** User reported no pitch variations in audio commentary  
**Root Cause:** Browser limitation + SSML approach didn't work  
**Solution:** Switched to Web Speech API native pitch property

---

## What Happened

### Initial Approach ❌
We implemented SSML prosody markers thinking the Web Speech API would parse them:
```
OpenAI Output: "[HIGH]Four![/HIGH]"
↓
Expected: Browser parses <prosody pitch="high"> and applies pitch
↓
Reality: Web Speech API doesn't process SSML properly for pitch
↓
Result: User heard "[HIGH]Four![/HIGH]" with NO pitch changes
```

### Discovery 🔍
Web Speech API in browsers:
- ✅ Supports pitch property on SpeechSynthesisUtterance object
- ❌ Does NOT reliably process SSML markup language
- ✅ Works great in Chrome/Edge
- ❌ Completely broken in Firefox/Safari (ignores pitch)

### New Approach ✅
Use the native `pitch` property directly on the utterance object:
```
Commentary: "[HIGH]Four![/HIGH]"
↓
Detect [HIGH] marker in text
↓
Set utter.pitch = 1.8 (high pitch)
↓
Result: "Four!" plays in high pitch ✅
```

---

## Current Implementation

### Backend (server/openai-commentary.js)
OpenAI generates commentary with prosody markers:
```
"[HIGH]Four![/HIGH] [EMPHASIS]Beautiful[/EMPHASIS] shot!"
"[LOW]Out...[/LOW] bowled!"
```

### Frontend (client/src/components/LiveMatch.js)

#### 1. Detect Markers
```javascript
if (next.text.includes('[HIGH]')) {
  utter.pitch = 1.8; // High pitch
} else if (next.text.includes('[LOW]')) {
  utter.pitch = 0.7; // Low pitch
} else {
  utter.pitch = 1.0; // Normal
}
```

#### 2. Display Clean Text
When displaying in UI, strip the markers:
```javascript
const stripSSMLTags = (text) => {
  return text
    .replace(/\[HIGH\](.*?)\[\/HIGH\]/g, '$1')
    .replace(/\[LOW\](.*?)\[\/LOW\]/g, '$1')
    .replace(/\[EMPHASIS\](.*?)\[\/EMPHASIS\]/g, '$1');
};
```

#### 3. Logging
Added console logs so users can verify pitch is being set:
```javascript
console.log('🎵 Pitch HIGH (1.8) applied:', next.text.substring(0, 60));
console.log('🎵 Pitch LOW (0.7) applied:', next.text.substring(0, 60));
```

## Browser Support

### ✅ Pitch Works (Use These for Demo)
- **Chrome 90+** - Full support
- **Edge 90+** - Full support
- **Opera 76+** - Full support

### ❌ Pitch Doesn't Work (Avoid)
- **Firefox** - Pitch property ignored (browser limitation)
- **Safari** - Pitch property ignored (browser limitation)

### Why?
Different browsers implement Web Speech API differently:
- Chrome/Edge: Use native OS speech APIs with full pitch support
- Firefox/Safari: Use OS speech APIs but intentionally don't expose pitch control

## Summary

### The Problem
"Audio sounds monotone despite dramatic commentary"

### The Root Cause
Web Speech API doesn't support SSML properly; pitch control is browser-specific

### The Solution
- Detect [HIGH]/[LOW] markers in text
- Set native `pitch` property on SpeechSynthesisUtterance
- Works great in Chrome/Edge, degrades in Firefox/Safari

### The Outcome
✅ Chrome/Edge users get full pitch variations
✅ All users get dramatic commentary text
✅ Graceful fallback (monotone but still engaging)
✅ Clear path to production (Google Cloud TTS)
